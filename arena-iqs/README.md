# ARENA IQS — Quality Platform (single file)

Open `ARENA_IQS.html` in a browser and load `New_Master_File.xlsx` from the top bar.

This one file replaces `ARENA_IQS_v70_1.html` and `ARENA_IQS_v70_2.html` (branch `ccr-5c44a9f5-039cn5`):

- all v70.1 content: rulebook rev-c2 cross-check fixes, Issue SRC page, print frame fix, and every module (Order Fulfilment, Issue SRC, Final Inspection Booking, Factories, Compliance Pathway, Master File Cross-Check, PPWR Packaging Forms, Turnover Reports, Supplier Scorecard, Risk Assessment, New vs Repeat Items)
- **FRI Validation Report** (sidebar, between Order Fulfilment and Issue SRC) — replaces Final Inspection Booking, which is removed. Built on the fri-validation skill v2.9: CP1–CP10 compliance matrix, findings F- / NC- / RG- / OB- with the pattern library #1–#26, AQL Ac/Re check per ISO 2859-1 Tables 1 & 2-A, requirement coverage (Step 3e), report verdict and an independent shipment status. An open NC- blocks Issue SRC; a withheld authorisation asks for confirmation. **Import report** reads an FRI report in Word (.docx), Excel (.xlsx/.xls/.csv) or PDF and pre-fills a new validation (P.O./lot matched to the master file, report no., date, inspector, reviewer, quantities, sampling levels, AQL, defects found, results; embedded photos counted); a register exported from this page is merged back. **Pre-validation** runs on import (and with ⚙ Run pre-validation): fills the CP1–CP10 matrix with the report lines that evidence each checkpoint, the report's own stated result and a pre-verdict, and extracts findings with the skill's rules (patterns #1, #2, #3, #4, #5, #6, #7, #9, #11, #13, #14; missing shipping marks / barcode scan / batch code / golden sample / ISPM 15 / disposal data / close-meeting acknowledgement; < 5 cartons measured; deviation > 3 %; AQL reject → NC-). Not evidenced while the report says Passed → Critical; no embedded photos → photo-dependent findings PROVISIONAL, capped at Major. Items are tagged auto; re-running replaces only auto items, and anything edited by hand is kept. **Requirement documents** (📎 Upload artwork & requirement docs, or section 0 of the workbench): P.O./P.I., approved artwork / print files, CE label / DoP / DoC, IM, test reports, QC Pack / QSD, ARENA FRI Standard checklist, Ally protocols — many files per type, Word / Excel / PDF / AI / images. Text and EAN-13 / ITF-14 codes (check-digit verified) are read; originals are kept in the browser (IndexedDB) and can be reopened. The FRI Standard checklist fills basis, coverage and the 'QS to fill' RG-. **P.O. reconciliation** (section 1b) compares the loaded master file (Order Fulfill + Orders Data) with the report and the documents: Ally, supplier, P.O. qty, packed ≥ 80 %, every item line (code / GTIN in the report and in the artwork), artwork GTINs not on the P.O. (NC-), brand, inspection date / company / result, ETD, gates (tech docs, golden sample, artwork), SRC already dated, P.O. status; recalculated on every master-file load and added to the pre-validation. **Evidence per finding**: on import the report's photos are extracted with their captions (Word: embedded photos, caption above/below; PDF: page images; Excel: anchored pictures with the nearby cells) and the same is done for uploaded documents. Every finding carries its references — matching report photos (by own caption), report text, master-file data (Order Fulfill / Orders Data) and document excerpts / pictures; when no photo matches it states "Reference photo: none available in the report." (never an unrelated image), and for an absence it records what was searched and the report's own claim. Reused photo files under different captions → #17. ＋ evidence links photos / notes by hand. Evidence goes into Print/PDF and the Word export (pictures embedded); thumbnails are stored in the browser (IndexedDB). **AQL — ARENA sampling method** (QS, 10 Nov 2026): lot size = order (shipment) q'ty; one item → normal single sampling, General II + S3 on the item; several items (one P.O. or across P.O. lots) → General II on Σ order q'ty, allocated per item round(n × item order q'ty ÷ Σ), S3 per item on its order q'ty, Ac/Re at the combined n; packed q'ty only for Σ packed ≥ 80 %. The report's "Table of shipment items and sampling details" is read on import and every item row is checked (pattern #5 / #6 / #14). The revised skill is in `skills/fri-validation/` (v3.0, plus an uploadable `fri-validation.skill`). **Export** to Excel (register, re-importable), Word (.docx validation assessment or register) or PDF (print → Save as PDF). PDF reading uses pdf.js 3.11.174 (Mozilla, Apache-2.0), embedded and loaded only when a PDF is imported; scanned (image-only) PDFs and old .doc files cannot be read. Validations are saved in the browser (localStorage) — export the register to share it or move to another computer. The Word deliverables (annotated report, supplier CAPA) stay with the skill.
